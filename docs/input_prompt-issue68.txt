# 調査依頼: 劣化耐性AI画像検出器の小規模学習パイロット計画 (DCPT + So-Fake-Set) の妥当性検証 (2026-09時点)

## 前提: 実運用の対象分布と達成目標

判定対象はSNS掲載画像。EXIF・メタデータは剥落し、長辺1024px縮小+JPEG Q75再圧縮相当の加工を通る。実写・生成の双方が同じ加工を通る。生成側はGPT Image 2系とNano Banana系が主対象。

運用目標は「実写への誤検知 FPR ≤ 0.1% を維持した上で生成画像を検出する」こと。accuracy/AUCではなく群単位の TPR@FPR=1%・0.1% を主指標とする。

## 前提: 実測結果 (自前コホート)

- コホート: 実写586群 (iPhone撮影、EXIFなしスクリーンショット・保存画像を含む) + 生成115群 (GPT Image 2系58 + Nano Banana系57)、双方にSNS相当加工済み。
- 受動検知の壊滅を確認済み: 誤検知0動作点での生成検出は UFD 0/91群、CuRe 0/91群、Community Forensics 1/91群、EFFORT 2/91群。SNS耐性をうたう外部検出器も届かない。
- So-Fake-R1 (Qwen2.5-VL-7B + LoRA、9段階VLMパイプライン) は当環境 (CPU のみ) で715群の推論が非現実的で未計測。NTIRE上位の公開手法群も重み未入手で未検証。
- 透かし計測 (OpenAI Content Provenance API、2026-09-25実測): GPT Image 2系画像のSynthIDはSNS相当加工後も 31/31 で100%検出。C2PAはAPI上 `not_detected` で一貫。実写で誤検知0。Nano Banana系は未計測。
- 実写群の高スコア裾はEXIFなしのスクリーンショット・保存画像 (kind=unknown) に集中すると確認済み。EXIF確認済み実写 (photo) のみを分母にすると検出率は大きく上がる。

## 検証対象の計画 (Issue #68 の方針)

追加学習による劣化耐性検出器の小規模パイロット:

1. DCPT (Degradation-Consistent Paired Training、同一画像のclean/degradedペアで特徴を揃える学習。論文報告: Synthbuster 8劣化条件平均でbaseline比BAcc +9.1pt、JPEG条件で+15.7〜17.9pt、推論コスト増なし) を学習方針の主軸にする。
2. NTIRE 2026 3位手法 LPT (基盤モデル + LoRA + 実劣化再現) の要素を小規模に取り入れる。
3. 学習データはSo-Fake-Set (約223万枚、32生成器、CC BY 4.0とされる) と自前生成画像 (Higgsfield)。So-Fakeが行う4拡散加工+スクリーンショット劣化を学習中に再現する。
4. 評価は学習に使っていない評価群で TPR@FPR(1%/0.1%) を測り、So-Fake-R1 (公開報告では So-Fake-OOD で72.0、1024+JPEG75で70.3/69.5程度) と同等以上なら継続。
5. 透かしで拾える生成器 (GPT Image 2系はSynthID 100%残存確認済み) は学習優先度から下げる。
6. NTIRE学習セットは114GBありストレージ50GB制限のため分割利用。

## 検証してほしい仮説

H1. DCPTはこの設定で機能する: DCPTの報告改善 (+9.1〜17.9pt) はSynthbuster等のベンチマークでの値であり、「GPT Image 2 / Nano Banana級の最新生成器 × 実写スクリーンショット混入 × FPR≤0.1%動作点」でも同程度の改善が期待できるか。低FPR動作点での効果を報告した研究はあるか。

H2. So-Fake-Setは学習データとして適切: ライセンス表記 (CC BY 4.0) と実際の再配布条件、実枚数・生成器内訳・real画像の取得元は公式通りか。学習側生成器と評価側生成器 (GPT Image 2 / Nano Banana) の分離は成立するか (So-Fake-Set内にGPT Image 2系/Nano Banana系が含まれるか)。含まれるなら評価群からの除外設計が必要。

H3. 小規模パイロットで有意な判断ができる: パイロット規模 (数千〜数万枚、LoRA級の部分学習) で「本コホートで効くか」を判定する際、効果量の期待値と必要な評価群サイズはどの程度か。実写群数百では TPR@FPR=0.1% の有意な改善検出が統計的に可能か (FPR 0.1% の証明には実写約3000群必要という計算がある)。

H4. 劣化再現の内挿が効く: So-Fakeの4拡散加工+スクリーンショット再現は、実際のSNS伝送 (Telegram/X/Instagram等の多重伝送、RRDataset等の実測) とどの程度一致するか。学習時劣化と評価時劣化のミスマッチによる過大評価のリスクと、それを防ぐ評価プロトコルはあるか。

H5. SynthID優先度戦略は妥当: 「SynthIDが残る生成器は受動検知の優先度を下げる」方針に対し、SynthID検出の実際のカバレッジ (全生成器の何割がSynthID/C2PAを付与するか、加工で失われる率、検出APIの可用性・コスト) はどの程度か。Nano Banana系にも同等の透かし残存があるか。

H6. より単純な代替がない: フル学習を避けつつ同等の効果を得る近道として、データ拡張のみのfine-tuning、公開済み重みの閾値再較正、So-Fake-R1等の公開重みを加工後コホートでそのまま使う、等の選択肢と比べて、自前DCPT学習の上積みはどこにあり、それはパイロット費用に見合うか。

## 調査論点

1. DCPT原論文の正確な条件: ベースモデル、学習データ規模、劣化セット、評価プロトコル、コード/重み公開の有無。報告値がFPR極小動作点を含むか。
2. So-Fake-Setの取得・ライセンス・構成の実態: ダウンロード方法、実容量、生成器リスト、real画像の由来、商用生成器の含有有無、派生物の再配布可否。
3. LPT (NTIRE 2026 3位) の実装詳細と再現性: 基盤モデル名、LoRAの適用位置、実劣化再現の内容、コード公開状況、学習に要した計算資源。
4. 低FPR運用での追加学習の前例: TPR@FPR≤1% や FPR≤0.1% の動作点で追加学習が効いた定量報告。失敗例 (裾が動かない、実写裾も同時に上がる) があればその機序。
5. パイロットのサンプルサイズ設計: 「効く/効かない」を判断するのに必要な学習枚数と評価群数の根拠。生成器leave-one-out評価の標準的手順。
6. 計算資源の見積もり: CLIP/DINOv2級バックボーン + LoRA + ペア学習をSo-Fake-Setの一部で回す際の、GPU種別ごとの現実的な学習時間と、50GB制限下でのデータ分割の実務。
